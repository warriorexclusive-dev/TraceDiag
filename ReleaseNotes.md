# Release Notes

История изменений TraceDiag. Готовые сборки публикуются на страницах
[Releases](https://github.com/warriorexclusive-dev/TraceDiag/releases).

## 1.8.4

- Добавлен чекбокс «Не фрагментировать (DF)», выключенный по умолчанию. При включении
  размер пакета ограничен `1024` байтами, динамический размер снимается и блокируется,
  а все зонды основной проверки и мониторинга идут с флагом `DontFragment`.
- Максимальный размер ICMP-пакета в поле ввода увеличен до безопасного значения `65500`
  байт; подпись поля формируется из тех же границ, что и сам ввод.
- Перед основной проверкой и один раз при старте мониторинга выполняется DF-предпроверка:
  по одному зонду на каждый найденный узел для размеров `64 → 128 → 256 → 1024 → 1400`.
  Успехи и ошибки пишутся в консоль и файловый лог, не меняя счётчики и диагнозы таблицы.
- Зонды обычной проверки, мониторинга и обнаружения маршрута создаются как отдельные
  задания с триггером; алгоритмы проверки и мониторинга выделены в независимые контроллеры.

## 1.8.3

- Чекбоксы снова стандартные: собственная отрисовка убрана вместе с наложением текста.
- Цвета стандартных чекбоксов меняются вместе с темой через палитру.
- Неактивные узлы показываются серым в тёмной и светлой темах.

## 1.8.2

- В тёмной теме чекбоксы и таблица рисуются палитрой темы: активный текст белый,
  фон и линии тёмные.
- Непроверяемые узлы с диагнозом `ICMP отключён` выделяются серым текстом.
- Отключённые элементы управления тоже используют серый цвет вместо чёрного.

## 1.8.1

- Чекбоксы перенесены в левую часть панели ввода и размещены в одной строке.
- Правая колонка стала уже, а верхняя панель занимает меньше высоты.

## 1.8.0

- Исправлено выравнивание подписи «Количество попыток (1-1000)» относительно поля ввода
  в обычном окне, при разворачивании и в полноэкранном режиме.
- Добавлен чекбокс «Режим постоянного мониторинга». Размер пакета берётся один раз из поля,
  количество попыток не используется. После обнаружения маршрута каждый доступный узел
  опрашивается собственным таймером раз в секунду; узлы с диагнозом `ICMP отключён`
  исключаются, узлы с ограничением размера пакета продолжают опрашиваться.
- Кнопка `Stop` останавливает мониторинг; состояние чекбокса сохраняется в `ui-state.json`.
- В режиме мониторинга повторные опросы обновляют строку узла, не добавляя новые строки.
- История статистики ограничена 1 000 000 снимков, буфер вывода — 10 000 строк.
  При превышении лимитов удаляются самые старые записи и строки.
- Файловый лог переключается на новый файл при достижении 4 МБ; предыдущий файл
  не изменяется. Запись лога и обработка статистики выполняются отдельными воркерами,
  не блокируя опрос сокетов.

## 1.7.0

- Удалена дополнительная проверка потерь повторными ICMP-запросами к предыдущему
  и текущему узлам.
- Столбец «Состояние» показывает процент потерь из основной проверки, а причина потерь
  остаётся в отдельном столбце «Диагноз».
- Исключены ложные статусы «поврежден: потеря между узлами» и «потеря также на предыдущем
  узле», когда большие ICMP-пакеты не проходят через узел.

## 1.6.0

- При закрытии окна сохраняются все поля ввода, чекбоксы, ширины столбцов таблицы
  и состояние окна: размер и позиция в пикселях или maximized.
- При запуске состояние интерфейса восстанавливается из отдельного файла
  `ui-state.json`. Повреждённый файл удаляется, и программа стартует со значениями
  по умолчанию.
- Ключ запуска `reset` принудительно удаляет сохранённое состояние интерфейса
  перед загрузкой.

## 1.5.0

- Добавлен столбец «Диагноз» в таблице статистики узлов.
- Узел получает диагноз `ICMP отключён`, если не отвечает ни на один размер пакета
  или был пропущен при обнаружении маршрута.
- Диагноз `Обрезка размера ICMP` выставляется, когда большие размеры пакета перестают
  отвечать или дают больше потерь, чем меньшие размеры у того же узла.
- Диагноз `Антифлуд ICMP` выставляется при частичных потерях пакетов без признаков
  ограничения размера. Диагнозы записываются в лог.

## 1.4.1

- При переходе к следующему размеру пакета счётчики отправленных и полученных пакетов,
  процент потерь и выборки RTT узла больше не сбрасываются.
- Средний, минимальный и максимальный пинг рассчитываются по всем накопленным замерам
  для узла, а не только по последнему размеру пакета.

## 1.4.0

- Кнопка `Run` во время проверки отображает `Stop` и прекращает текущий запуск.
- Размеры пакета перебираются по узлам: сначала все значения для одного узла
  (`64 → 128 → 256 → 512 → 1024`), затем следующий узел.
- Поле задержки переименовано в «Задержка при потере, мс». Задержка применяется
  только после пропущенного пакета; ответы обрабатываются без ожидания.
- После первой потери задержка действует на все последующие проверки этого узла,
  включая контроль потерь. Значение `0` отключает задержку.

## 1.3.0

- Добавлено поле «Задержка ICMP, мс» в правой панели; значение по умолчанию — `1000` мс.
- Задержка применяется после каждого ICMP-ответа при обнаружении маршрута, основных
  проверках узла и контроле потерь. Это снижает число ложных потерь на оборудовании
  с защитой от ICMP flood.
- Значение `0` отключает задержку; верхняя граница поля — `60000` мс.
- Цвет чекбоксов теперь задаётся палитрой темы одинаково для тёмного и светлого оформления.

## 1.2.1

- Исправлена ошибка, после которой повторный запуск с корректным узлом не работал, если
  предыдущая попытка завершилась на этапе проверки ввода.
- Неспецифицированные адреса (`0.0.0.0`, `::`) больше не принимаются как узел назначения.
- Проверка потерь больше не отправляет ICMP-запросы на узлы-заглушки без ответа: для сравнения
  используется предыдущий ответивший узел.

## 1.2.0

- Добавлена тёмная тема с переключателем в правой панели; по умолчанию включена тёмная тема.
- Выбор темы сохраняется в `settings.json` и восстанавливается при запуске.
- В качестве иконки приложения используется `cable_24dp.ico`.

## 1.1.2

- Количество попыток по умолчанию увеличено с `4` до `100`.

## 1.1.1

- Поиск хостов вынесен в отдельную модель `HostDiscovery`.
- Поиск выполняется последовательно по TTL: до `3` проходов с интервалом `1` с,
  пакет `64` байт, флаг `DontFragment` и таймаут `5` с.
- TTL без ответа добавляются в таблицу со статусом `не отвечает` и помечаются как
  пропускаемые; DNS и основная проверка такие записи не трогают.

## 1.1.0

- Лимит трассировки увеличен до `255` хопов.
- Исправлено завышение счётчиков в таблице: контрольные проверки потерь больше не
  добавляются к отправленным и полученным пакетам.
- Добавлен установщик .NET 10 Desktop Runtime и сборка дистрибутива для чистого ПК.
