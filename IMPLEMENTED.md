# Реализованные фитчи

Функционал, который уже сделан и проверен. Перенесено из `FEATURES`, чтобы план содержал только активные пункты. Нумерация сохранена от исходного плана.

1. Jitter и стандартное отклонение RTT по каждому узлу: таблица, консоль, JSON. Готово.
   Сэмплы RTT уже сохраняются.
2. IPv6: ICMPv6-трассировка и разрешение AAAA-записей в обоих хостах. Готово.
3. Обнаружение смены маршрута и балансировки ECMP по разным IP-источникам ответов
   в пределах одного узла; состояние узлов уже хранится. Готово.
3.1. Отображение нескольких диагнозов одновременно: обрезка пакета, ICMP anti-flood
   и ECMP-балансировка в одной ячейке/строке, а не только первая причина. Готово.
4. Расширение автоматических диагнозов: MTU black hole, асимметрия маршрута,
   блокировка ICMP промежуточными узлами, фильтрация по порту/NAT. Готово.
5. ASN-локап через DNS Team Cymru и отдельная колонка с номером автономной системы. Готово.
   При отсутствии PTR владелец пула IP подтягивается из RIPEstat; запрос включается по умолчанию
   и отключается галочкой в GUI или флагом `--no-ripe` в консоли. Готово.
5.1. Опциональный асинхронный precheck альтернативных маршрутов для нескольких DNS/IP-целей.
    DNS-серверы берутся из dns-servers.json, запросы идут пачкой с таймаутом 3000 мс
    и общим дедлайном 2–3 минуты. Номера маршрутов замораживаются до основной проверки,
    отклонения пишутся на тот же номер; есть fallback на исходный алгоритм.
    Вывод: дерево host → route → hop, в логах подпись host / route / hop, поля run_id/started_at.
    По умолчанию 4 сигнатуры потока, в глубоком режиме 8. Готово.
5.2. Защита от дурака в консоли: без параметров запрашивается хост, невалидный ввод
    сопровождается ошибкой и повторным вопросом, дальше запуск с параметрами по умолчанию.
    Ключи командной строки вынесены в общий модуль CommandLineSettingsArg для повторного
    использования в Windows- и Linux-GUI. Готово.
5.3. Системный DNS из сетевой карты используется обязательно везде, включая IPv6-серверы;
    альтернативные резолверы из dns-servers.json подключаются по умолчанию, но отключаются
    флагом `--no-alt-dns` и галочкой в Windows-GUI, как и RIPE. Дополнительно капшен окна
    Windows-GUI перекрашивается вместе с тёмной/светлой темой через DWM. Готово.
5.4. Главное окно Windows-GUI: только имя хоста, иконки play/stop/settings, таблица,
    вывод и статус. Все остальные настройки вынесены в отдельное окно с пятью группами:
    подключение, внешние источники, режимы работы, интерфейс, опции проверки.
    Иконки SVG рендерятся через Svg.NET в 16/32/64/72/96/128 px цветом из темы.
    Явный выбор сетевого адаптера привязывает ICMP и DNS к исходному адресу через RAW-сокет:
    Windows запрашивает права манифестом, Linux — root; без прав опция недоступна
    с подписью внизу окна, а зонды остаются обычным ICMP. Для приватной/внутренней цели
    внешние источники (RIPE, ASN, альтернативные DNS) отключаются автоматически.
    Редактор списка альтернативных DNS проверяет IP и факт ответа резолвера, путь хранится
    в настройках (по умолчанию AppData Windows / home Linux). Добавлены ключи
    `--adapter`, `--no-asn`, `--dns-file`. Готово.
5.5. Исправления после проверки 1.9.9: выбранный язык в окне настроек теперь берётся из
    конфигурации и список языков переведён при смене языка; лейбл удалённого хоста
    прижат к верхней границе строки тулбара и выровнен с полем ввода; редактор ДНС
    подхватывает штатный `dns-servers.json` из каталога программы, если пользовательского
    файла ещё нет. Готово.
5.6. Исправления после проверки 1.9.10: добавлены размеры иконок 16 и 32 px, по умолчанию
    теперь 32 px; углубленная проверка пишет в лог цель, резолвер, каждый поток и итог,
    поэтому ход проверки виден в консоли; в таблице снова отображаются маршрут и цель —
    метаданные маршрута теперь передаются в накопитель статистики и не перезаписываются
    между маршрутами; внутренний дедлайн предварительной проверки маршрутов больше не
    маскируется под отмену проверки пользователем, а завершается резервными маршрутами.
    Готово.
