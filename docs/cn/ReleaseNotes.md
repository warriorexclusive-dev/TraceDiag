TraceDiag 的变更历史。预编译版本发布在 [Releases](https://github.com/warriorexclusive-dev/TraceDiag/releases) 页面。

## 1.9.11

- 新增 16/32 px 图标尺寸（默认 32）、深度预检查日志、统计表中的路由/目标列；内部超时不再被误判为用户取消。

## 1.9.10

- 修复设置窗口语言选择、远程主机标签对齐以及从程序目录加载自带 dns-servers.json。

## 1.9.9

- 新主窗口：主机、播放/停止/设置图标、表格、输出和状态；其余设置移至独立窗口。通过 RAW 套接字指定适配器，新增 DNS 编辑器及 --adapter、--no-asn、--dns-file。

## 1.9.8

- 所有位置强制使用网卡的系统 DNS（含 IPv6）；备用解析器默认启用，可用 --no-alt-dns 或界面关闭。窗口标题随主题变化。

## 1.9.7

- 控制台无参数启动时提示输入主机，输入无效会报错；命令行键名提取到公共模块。

## 1.9.6

- 异步备用路由预检查：dns-servers.json、单次查询 3000 毫秒、总时限 150 秒、4 个流签名（深度模式 8 个），失败时回退。

## 1.9.5

- 通过 Team Cymru DNS TXT 查询 ASN 并新增独立列；默认从 RIPEstat 获取地址池拥有者，可用 --no-ripe 关闭。私网目标自动关闭外部数据源。

## 1.9.4

- 初步的 ASN 查询和独立的自治系统列。

## 1.9.3

- 扩展自动诊断：MTU 黑洞、路由不对称、中间节点阻断 ICMP、端口/NAT 过滤。

## 1.9.2

- 同一行显示多个诊断：数据包截断、ICMP 防洪泛和 ECMP 均衡。

## 1.9.1

- 按同一跳内不同 IP 响应来源检测路由变化和 ECMP。

## 1.9.0

- 新增界面语言 `En`, `Cn`, `Fr`, `De`, `Ru`, `Jp`；默认为 `En`。选择保存在 `settings.json` 中，在 GUI 中可无需重启而切换，在控制台中通过 `--language <en|cn|fr|de|ru|jp>` 选项指定。译文保存在可执行文件旁的 `localizations/*.json` 中，无需重新编译。GUI 和控制台中所有可见字符串均已本地化，包括检查进度信息和最终表格；由于规范文本与显示的译文相互分离，文件日志仍保持英文。
- Windows GUI 中在表格与日志之间新增了可拖动的分隔条：可用鼠标调整两个面板的高度，位置以百分比形式（带范围限制）保存在 `ui-state.json` 中，并在启动时恢复。
- 业务逻辑已迁移到 `TraceDiag.Core`（`netstandard2.0`）；WinForms 宿主已改用 .NET Framework 4.8，可在 Windows 7 SP1 / Server 2008 R2 SP1 上运行。
- 新增控制台宿主 `TraceDiag.Console`，支持 `net48`（无 GUI 的 Windows Server 2008 R2）和 `net10.0`（Ubuntu 22.04+ 和 Windows Server 2012+）。提供 `run`、`monitor` 和 `reset` 命令，输出格式 `plain`、`csv` 和 `json`，并可通过 `Ctrl+C` 停止。检查进度逐行输出到控制台，同时通过 `AsyncLogWriter` 逐行写入文件日志；完成后最后只打印一张 `Summary:` 汇总表格。WinForms 的行为未改变。
- 未知选项现在会提示最接近的名称并给出完整的选项列表；控制台的所有用户界面字符串和日志字符串均已加入 `Strings.cs`；控制台复用核心的服务、文件日志和轮换机制。
- 为较旧的 framework 目标添加了 polyfill 和 API 替代实现（`PeriodicTimer`、`TickCount64`、`Math.Clamp`、`IReadOnlySet`、`ArgumentNullException.ThrowIfNull`、带令牌的 `Dns.GetHostAddressesAsync`）。
- Windows 安装程序通过注册表检查 .NET Framework 4.8；若未安装，则需要管理员权限，并从本地文件或替代仓库获取离线安装程序（`-Framework48InstallerPath` / `-Framework48Url`）；不会从 Microsoft 网站下载。Linux 控制台以 self-contained tar.gz 形式提供，附带 `install-console.sh`，无需单独的运行时。
- 新增系统安装包：适用于 Windows x86 和 x64 的 MSI（带 .NET Framework 4.8 检查及«开始»菜单快捷方式），以及适用于 Linux amd64 和 arm64 的 deb（独立控制台和 `tracediag` 命令）。构建使用 `installer\Build-TraceDiag-Packages.ps1`。压缩包中新增了适用于 `linux-arm64` 的控制台版本。
- README 和 Release Notes 已翻译为 `En`, `Cn`, `Fr`, `De`, `Ru`, `Jp`，并以单独文件存放在 `docs/<语言>/` 中。
- Linux GUI 计划作为后续独立工作：Core 架构已准备好接入第二个 UI 适配器，而无需修改业务逻辑。

## 1.8.4

- 新增«不分片 (DF)»复选框，默认未勾选。启用后，数据包大小被限制为 `1024` 字节，动态大小会被取消并禁用，主检查和监控的所有探测包都会带上 `DontFragment` 标志。
- 输入框中 ICMP 数据包的最大值提高到安全值 `65500` 字节；字段标签与输入本身使用相同的边界生成。
- 在主检查之前以及监控启动时各执行一次 DF 预检查：针对每个发现的节点，分别按 `64 → 128 → 256 → 1024 → 1400` 大小发送一个探测包。成功和错误都会写入控制台和文件日志，不会改变表格中的计数器和诊断。
- 常规检查、监控和路由发现的探测包均作为带触发器的独立任务创建；检查算法和监控算法被拆分到相互独立的控制器中。

## 1.8.3

- 复选框恢复为标准样式：自定义绘制连同文本叠加一并移除。
- 标准复选框的颜色通过调色板随主题变化。
- 非活动节点在深色和浅色主题下均显示为灰色。

## 1.8.2

- 深色主题下，复选框和表格使用主题调色板绘制：活动文本为白色，背景和线条为深色。
- 诊断为 `ICMP 已禁用` 的不可检查节点以灰色文本标示。
- 禁用的控件也使用灰色而非黑色。

## 1.8.1

- 复选框移至输入面板左侧，并排列在同一行中。
- 右列变窄，顶部面板占用的高度也减小。

## 1.8.0

- 修正了«尝试次数 (1-1000)»标签相对于输入框的对齐问题，涵盖普通窗口、最大化时和全屏模式。
- 新增«持续监控模式»复选框。数据包大小只从字段读取一次，不使用尝试次数。发现路由后，每个可用节点由各自的计时器每秒轮询一次；诊断为 `ICMP 已禁用` 的节点会被排除，数据包大小受限的节点仍继续轮询。
- `Stop` 按钮可停止监控；复选框状态保存在 `ui-state.json` 中。
- 在监控模式下，重复轮询会更新节点所在行，而不会添加新行。
- 统计历史记录限制为 1 000 000 个快照，输出缓冲区限制为 10 000 行。超出限制时，最旧记录和行会被删除。
- 文件日志达到 4 MB 时会切换到新文件；之前的文件保持不变。日志写入和统计处理由独立的工作线程执行，不会阻塞套接字轮询。

## 1.7.0

- 移除了通过向前一个和当前节点重复发送 ICMP 请求来进行的额外丢包检查。
- «状态»列显示主检查得到的丢包百分比，丢包原因仍保留在单独的«诊断»列中。
- 当较大的 ICMP 数据包无法通过某节点时，不再出现«损坏：节点间丢包»和«前一节点也有丢包»这两种误报状态。

## 1.6.0

- 关闭窗口时会保存所有输入框、复选框、表格列宽以及窗口状态：按像素表示的尺寸和位置，或 maximized。
- 启动时界面状态从单独的 `ui-state.json` 文件恢复。损坏的文件会被删除，程序以默认值启动。
- 启动参数 `reset` 会在加载前强制删除已保存的界面状态。

## 1.5.0

- 节点统计表中新增«诊断»列。
- 如果节点对任何数据包大小都没有响应，或在路由发现时被跳过，则会获得 `ICMP 已禁用` 诊断。
- 当较大的数据包尺寸不再响应，或在同一节点上比较小的尺寸产生更多丢包时，会给出 `ICMP 大小限制` 诊断。
- 当出现部分丢包但没有尺寸限制迹象时，会给出 `ICMP 防洪泛` 诊断。诊断会写入日志。

## 1.4.1

- 切换到下一个数据包大小时，已发送和已接收数据包计数器、丢包百分比以及节点的 RTT 采样不再重置。
- 平均、最小和最大 ping 值根据该节点累积的所有测量值计算，而不仅仅是最后一个数据包尺寸。

## 1.4.0

- `Run` 按钮在检查期间显示为 `Stop`，并停止当前运行。
- 数据包大小按节点逐一遍历：先处理一个节点的所有取值（`64 → 128 → 256 → 512 → 1024`），再处理下一个节点。
- 延迟字段已重命名为«丢包延迟，毫秒》。延迟仅在数据包丢失后应用；响应会被立即处理，不作等待。
- 首次丢包后，延迟会作用于该节点的所有后续检查，包括丢包检查。值 `0` 会关闭延迟。

## 1.3.0

- 右侧面板新增«ICMP 延迟，毫秒»字段；默认值为 `1000` 毫秒。
- 在路由发现、节点主检查和丢包检查期间，每次 ICMP 响应后都会应用延迟。这能减少在带有 ICMP flood 防护的设备上出现误报丢包的情况。
- 值 `0` 会关闭延迟；字段上限为 `60000` 毫秒。
- 复选框颜色现在由主题调色板统一设定，深色和浅色外观采用相同方式。

## 1.2.1

- 修复了一个错误：如果上一次尝试在输入验证阶段结束，那么随后使用正确节点重新启动将无法工作。
- 非指定地址（`0.0.0.0`、`::`）不再被接受为目标节点。
- 丢包检查不再向无响应的占位节点发送 ICMP 请求：比较时使用前一个作出响应的节点。

## 1.2.0

- 新增深色主题，右侧面板中有切换开关；默认启用深色主题。
- 主题选择保存在 `settings.json` 中，并在启动时恢复。
- 应用图标使用 `cable_24dp.ico`。

## 1.1.2

- 默认尝试次数从 `4` 增加到 `100`。

## 1.1.1

- 主机发现功能被拆分到独立的 `HostDiscovery` 模型中。
- 发现按 TTL 顺序执行：最多 `3` 轮，间隔 `1` 秒，数据包 `64` 字节，带 `DontFragment` 标志，超时 `5` 秒。
- 无响应的 TTL 会以 `无响应` 状态添加到表格中，并标记为跳过；DNS 和主检查不会触碰这些记录。

## 1.1.0

- 路由跟踪限制提高到 `255` 跳。
- 修复了表格中计数偏高的问题：丢包检查不再计入已发送和已接收的数据包。
- 新增 .NET 10 Desktop Runtime 安装程序，以及面向全新电脑的发行包构建。
