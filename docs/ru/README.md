# TraceDiag

> Языки: [English](../en/README.md) · [中文](../cn/README.md) · [Français](../fr/README.md) ·
> [Deutsch](../de/README.md) · [Русский](../ru/README.md) · [日本語](../jp/README.md)

Утилита для диагностики маршрута до удалённого хоста. Собирает ICMP-трассировку,
разрешает имена узлов, измеряет потери и проверяет устойчивость маршрута к разным размерам
пакета. Канонические строки находятся в `Strings.cs`, а переводы — в JSON-файлах папки
`localizations` рядом с исполняемым файлом. Бизнес-логика разбита на небольшие статические
модули.

Общая логика живёт в `TraceDiag.Core` (`netstandard2.0`) и не зависит от UI. Поверх неё
работают два хоста: WinForms (`net48`) и консоль (`net48` и `net10.0`). Консоль позволяет
использовать диагностику на Windows Server 2008 R2 без графического интерфейса и на
Linux (Ubuntu 22.04+).

## Возможности

- Трассировка маршрута: TTL от `1` до `255` (максимум, допустимый для IP TTL), остановка при
  достижении цели или по достижении лимита хопов.
- Поиск хостов вынесен в отдельную модель `HostDiscovery`: TTL опрашиваются последовательно,
  до `3` проходов, пакет `64` байт, таймаут `5` с. Флаг `DontFragment` включается,
  когда включён режим «Не фрагментировать». TTL без ответа получают статус `не отвечает`
  и пропускаются при проверке.
- Задержка при потере пакета настраивается полем «Задержка при потере, мс» справа,
  по умолчанию `1000` мс. Ответы обрабатываются без ожидания; после первого пропущенного
  пакета все последующие проверки этого узла идут с задержкой, чтобы не вызывать ложные
  потери из-за защиты оборудования от ICMP flood. Значение `0` отключает задержку.
- Reverse DNS для каждого обнаруженного узла с защитой от медленного ответа.
- Режим размера пакета:
  - галочка **«Динамический размер пакета»** включена — `64 → 128 → … → максимум`;
  - галочка выключена — только максимальный размер из поля ввода (`64–65500` байт).
  - все размеры сначала проверяются на текущем узле, затем очередь переходит к следующему;
  - при смене размера счётчики узла и выборки RTT сохраняются и продолжают накапливаться.
- Чекбокс **«Не фрагментировать (DF)»** по умолчанию выключен. При включении максимальный
  размер пакета ограничен `1024` байтами, динамический размер снимается и блокируется,
  а обнаружение маршрута, основная проверка и мониторинг используют `DontFragment`.
- Перед основной проверкой и один раз при старте мониторинга выполняется DF-предпроверка:
  по одному зонду на узел размером `64 → 128 → 256 → 1024 → 1400` байт. Все ответы и ошибки
  попадают в консоль и лог как дополнительная информация; таблица и диагнозы не меняются.
- Зонды создаются отдельными заданиями с триггером `DO_NOT_FRAGMENT` или обычным триггером.
  Алгоритм конечной проверки и алгоритм мониторинга живут в независимых контроллерах.
- Настраиваемое количество попыток на узел: `1–1000`, по умолчанию `100` — для отчёта
  провайдеру и замера процента потерь.
- Чекбоксы размещены в левой части панели ввода одной строкой; правая колонка уже,
  а сама панель занимает меньше высоты.
- Чекбокс **«Режим постоянного мониторинга»**: размер пакета берётся один раз из поля,
  число попыток не используется. После обнаружения маршрута каждый узел опрашивается
  отдельным таймером раз в секунду. Узлы с диагнозом `ICMP отключён` не опрашиваются,
  ограничение размера пакета не исключает узел из мониторинга. Остановка — кнопкой `Stop`.
- В режиме мониторинга данные каждого узла обновляются в его существующей строке,
  новые строки для повторных опросов не создаются.
- История статистики ограничена `1 000 000` снимков, буфер вывода — `10 000` строк:
  при переполнении удаляются первые записи и строки. Лог переключается на новый файл
  при достижении `4` МБ, предыдущий файл остаётся без изменений. Запись лога и обработка
  статистики идут в отдельных воркерах, не занимая потоки ICMP-опроса.
- Точная статистика по каждому узлу: средний, минимальный, максимальный и последний пинг,
  количество отправленных/полученных пакетов, процент потерь. Среднее значение считается
  из всех сохранённых замеров RTT, а не из приблизительных величин.
- При `100%` потерях узел получает статус `не отвечает`, после `10` последовательных
  неудач проверка узла прекращается, а на следующих размерах пакета он пропускается.
- Потери отображаются в столбце «Состояние» как процент, причина — в отдельном столбце
  «Диагноз». Повторные проверки предыдущих узлов не выполняются.
- Языки интерфейса: `En`, `Cn`, `Fr`, `De`, `Ru`, `Jp`. По умолчанию `En`; выбор хранится
  в `settings.json`. В GUI язык меняется списком в правой панели без перезапуска,
  в консоли — опцией `--language <en|cn|fr|de|ru|jp>`. Переводы лежат в `localizations/*.json`
  рядом с exe и редактируются без пересборки; неизвестные ключи остаются английскими.
  Файловый лог всегда английский.
- Таблица статистики над логом на всю ширину окна; между ними — перетаскиваемый
  горизонтальный разделитель. Положение сохраняется отдельно от ширин столбцов.
  Отдельный столбец «Диагноз» показывает: `ICMP отключён`, `Обрезка размера ICMP`,
  `Антифлуд ICMP` или `—`, если признаков нет. Диагноз также пишется в лог.
- Выбор размера шрифта лога, задержки при потере и крупная кнопка `Run`/`Stop`
  в правой панели: во время проверки кнопка останавливает запуск.
- Полноэкранный режим: `F11` — включить/выключить, `Esc` — выйти.
- Тёмная тема по умолчанию с переключателем в левой панели; выбор сохраняется в настройках.
  Чекбоксы остаются стандартными и меняют цвета вместе с темой; таблица использует палитру темы,
  а непроверяемые узлы серые в тёмной и светлой темах.
- При закрытии окна отдельный файл `ui-state.json` сохраняет все поля ввода, чекбоксы,
  ширины столбцов таблицы, вертикальное положение разделителя (процент высоты таблицы)
  и состояние окна: развёрнуто по пикселям (`x, y, x2, y2`) или maximized. При запуске состояние восстанавливается; повреждённый файл удаляется,
  и программа стартует со значениями по умолчанию.
- Ключ запуска `reset` (например, `TraceDiag.exe reset`) принудительно удаляет сохранённое
  состояние интерфейса перед загрузкой.
- Собственная иконка `cable_24dp.ico`, файловое логирование и сохранение настроек в JSON.

## Консоль

```text
TraceDiag.Console run    --host <ip|domain> [--packet-size <n>] [--attempts <n>] [--loss-delay <ms>] [--dynamic] [--df] [--format plain|csv|json] [--language en|cn|fr|de|ru|jp]
TraceDiag.Console monitor --host <ip|domain> [--packet-size <n>] [--loss-delay <ms>] [--df] [--format plain|csv|json] [--language en|cn|fr|de|ru|jp]
TraceDiag.Console reset [--language en|cn|fr|de|ru|jp]
```

- Значения по умолчанию: размер пакета `1024`, попыток `100`, задержка `1000` мс.
- `--format plain` — текст, `csv` — CSV-строки, `json` — JSON Lines с полем `kind`.
- `--language` локализует справку, ошибки, статусы, строки хода проверки и итоговую
  таблицу. Файловый лог остаётся английским: каноничный текст и аргументы отделены
  от отображаемого перевода; имена опций и команды не переводятся.
  Консоль выводит текст в UTF-8 (в старых терминалах Windows может потребоваться `chcp 65001`).
- Ход проверки выводится в консоль построчно, сразу при записи в файловый лог,
  без накопления до конца проверки. Файл пополняется той же строкой через
  `AsyncLogWriter`, поэтому уже записанные строки сохраняются при отмене или закрытии.
- После завершения (в том числе после `Ctrl+C`) последней печатается одна итоговая
  таблица (локализованный аналог `Summary:`) с последними значениями по каждому TTL.
- WinForms-приложение работает как прежде: таблица обновляется прямо в интерфейсе.
- При опечатке в названии опции консоль подсказывает ближайшее корректное имя
  и печатает полный список опций для сравнения.
- `Ctrl+C` останавливает мониторинг; коды выхода: `0` успех, `1` ошибка, `2` неверные
  аргументы, `130` отмена.
- Консоль использует те же сервисы, логи и ротацию, что и WinForms-приложение.
- На Linux для ICMP от обычного пользователя может понадобиться
  `net.ipv4.ping_group_range` или capability `CAP_NET_RAW`.

## Требования

- WinForms: Windows 7 SP1 / Server 2008 R2 SP1 или новее, .NET Framework 4.8.
- Консоль `net48`: Windows 7 SP1 / Server 2008 R2 SP1 или новее, .NET Framework 4.8.
- Консоль `net10.0`: Windows Server 2012+, Ubuntu 22.04/24.04/26.04 и другие
  поддерживаемые .NET 10 системы; Linux-пакет self-contained, отдельный Runtime не нужен.
- Для сборки: .NET 10 SDK; для MSI — WiX 5 (`dotnet tool restore`), для deb — WSL с `dpkg-deb`.
  Установка .NET Framework 4.8 на legacy-Windows требует прав администратора и локального
  установщика из альтернативного репозитория (см. ниже).

планировщик размеров пакета, статистику узлов, маппинг ICMP-ответов, конфигурацию,
логирование, сохранение состояния интерфейса, локализацию на всех шести языках, разбор
аргументов консоли, форматы вывода, диагностические модули и полный цикл
`TraceDiagnosticsService` с тестовыми фейками
ICMP, DNS и логера.

## Установка на чистый ПК

Архивы (пер-user установка и «распаковать и запустить»):

```powershell
cd installer
.\Publish-TraceDiag.ps1
```

Скрипт публикует WinForms и консоль `net48` в `installer\App`, self-contained консоль
`net10.0` в `installer\ConsoleLinux` (`linux-x64`) и `installer\ConsoleLinux-arm64`,
копирует `localizations\` во все папки и собирает архивы:

- `installer\TraceDiag-install.zip` — Windows: GUI + консоль `net48` и установщик;
- `installer\TraceDiag-console-linux-x64.tar.gz` — консоль для Linux/amd64;
- `installer\TraceDiag-console-linux-arm64.tar.gz` — консоль для Linux/arm64.

На Windows распакуйте первый архив и запустите `Install-TraceDiag.cmd`. Установщик
проверяет .NET Framework 4.8 по реестру. Если его нет, положите `dotNetFx48_Full.exe`
рядом со скриптом (скрипт публикации добавит его в архив) или передайте
`-Framework48InstallerPath` / `-Framework48Url` для альтернативного репозитория.
Прямая загрузка с сайта Microsoft не используется. Установщик копирует файлы в
`%LOCALAPPDATA%\Programs\TraceDiag` и создаёт ярлык в меню «Пуск».

На Linux распакуйте нужный tar.gz и запустите `bash install-console.sh`; скрипт скопирует
self-contained файлы в `~/.local/share/TraceDiag` и создаст символическую ссылку
в `~/.local/bin`. Отдельный .NET Runtime скачивать не нужно.

Системные пакеты (per-machine):

```powershell
cd installer
dotnet tool restore
.\Build-TraceDiag-Packages.ps1
```

Результат — в `installer\dist`: `TraceDiag-<версия>-x86.msi`, `TraceDiag-<версия>-x64.msi`,
`tracediag_<версия>_amd64.deb` и `tracediag_<версия>_arm64.deb`. MSI содержит GUI и консоль
соответствующей разрядности, `localizations\` и ярлыки в меню «Пуск»; перед установкой
проверяется .NET Framework 4.8. deb-пакеты ставят консоль в `/usr/share/tracediag` и
создают команду `tracediag` через `/usr/bin`. Для deb требуется WSL с `dpkg-deb`.

Подробности: [installer/README-Installer.md](../../installer/README-Installer.md).
Скомпилированные файлы (`installer\App`, `installer\ConsoleLinux*`, `installer\build`,
`installer\dist`, архивы) в Git не попадают.

## Структура проекта

```text
TraceDiag.Core/              netstandard2.0, бизнес-логика без привязки к UI
  Models/                    данные, задания зондов и расчёт статусов узлов
  Services/                  ICMP, DNS, конфигурация, логирование
  Services/Abstractions/     контракты контроллеров, заданий и триггеров
  Services/Diagnostics/      маршрут, предпроверка DF, проверка узлов и диагноз потерь
  Services/Monitoring/       независимые таймеры узлов и запуск мониторинга
  Services/Logging/          ротация файлов и фоновая запись лога
  Compatibility/             полифиллы для netstandard2.0 и net48
  Localization/              чтение JSON-переводов и выбор языка
  Strings.cs                 канонические пользовательские и лог-строки
localizations/               en/cn/fr/de/ru/jp.json — переводы интерфейса
docs/                        en/cn/fr/de/ru/jp — README.md и ReleaseNotes.md на 6 языках
TraceDiag/                   net48, WinForms-хост
  Ui/                        фабрики контролов, layout, потоки запуска и политика размера
TraceDiag.Console/           net48 + net10.0, консольный хост
TraceDiag.Tests/             net48, тесты WinForms и ядра
TraceDiag.Console.Tests/     net48 + net10.0, тесты консоли и совместимости
installer/
  Install-TraceDiag.ps1      установка на Windows (per-user)
  install-console.sh         установка консоли на Linux
  Publish-TraceDiag.ps1      сборка архивов
  Build-TraceDiag-Packages.ps1  сборка MSI (x86/x64) и deb (amd64/arm64)
  wix/                       источники MSI
  deb/                       скрипт сборки deb в WSL
.config/dotnet-tools.json    закреплённая версия WiX 5
```

## Данные приложения

- Windows: `%LOCALAPPDATA%\TraceDiag\` (`settings.json`, `ui-state.json`, `logs\`).
- Linux: `~/.local/share/TraceDiag/` — те же файлы, создаются при первом запуске консоли.
- Логи: `tracediag-yyyyMMdd.log`; при достижении 4 МБ создаются
  `tracediag-yyyyMMdd-1.log`, `tracediag-yyyyMMdd-2.log` и так далее.
