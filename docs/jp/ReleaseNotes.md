TraceDiag の変更履歴です。ビルド済みパッケージは [Releases](https://github.com/warriorexclusive-dev/TraceDiag/releases) ページで公開されています。

## 1.9.11

- 16/32 px アイコンサイズ（既定 32）、詳細モードのログ、統計テーブルのルート/対象列を追加。内部期限切れをユーザーキャンセルと誤表示しなくなりました。

## 1.9.10

- 設定画面の言語選択、リモートホスト ラベルの配置、同梱 dns-servers.json の読み込みを修正。

## 1.9.9

- 新しいメイン ウィンドウ：ホスト、再生/停止/設定アイコン、テーブル、出力、ステータス。その他の設定は別ウィンドウ。RAW ソケットによるアダプター指定、DNS エディター、--adapter、--no-asn、--dns-file を追加。

## 1.9.8

- ネットワーク カードのシステム DNS を IPv6 含め常に使用。代替リゾルバーは既定で有効、--no-alt-dns または GUI で無効化。ウィンドウ キャプションがテーマに追従。

## 1.9.7

- 引数なしのコンソール起動でホストを入力させ、不正な入力をエラー表示。コマンドライン キーを共通モジュールに移動。

## 1.9.6

- 代替ルートの非同期事前チェック：dns-servers.json、1 クエリ 3000 ms、全体 150 秒、4 つのフロー シグネチャ（詳細モードは 8）、失敗時はフォールバック。

## 1.9.5

- Team Cymru の DNS TXT で ASN を取得し専用列を追加。PTR がない場合は既定で RIPEstat から所有者を取得、--no-ripe で無効化。プライベート対象では外部ソースを無効化。

## 1.9.4

- ASN 検索の初期版と自律システムの専用列。

## 1.9.3

- 自動診断を拡張：MTU ブラックホール、経路非対称、中継ノードによる ICMP 遮断、ポート/NAT フィルタリング。

## 1.9.2

- 1 行に複数診断を表示：パケット截断、ICMP アンチフラッド、ECMP バランシング。

## 1.9.1

- 同一ホップ内の異なる IP 応答元から経路変更と ECMP を検出。

## 1.9.0

- インターフェイス言語 `En`, `Cn`, `Fr`, `De`, `Ru`, `Jp` を追加しました。既定値は `En` です。選択は `settings.json` に保存され、GUI では再起動なしで変更でき、コンソールでは `--language <en|cn|fr|de|ru|jp>` オプションで指定します。翻訳は実行ファイルの隣にある `localizations/*.json` に保存され、再ビルドは不要です。検査の進行状況と最終テーブルを含む、GUI とコンソールの表示されるすべての文字列がローカライズされています。ファイルログは、カノニカルなテキストと表示用の翻訳を分離することで英語のままです。
- Windows GUI のテーブルとログの間にドラッグ可能なスプリッターを追加しました。パネルの高さをマウスで変更でき、位置は `ui-state.json` に割合として (範囲制限付きで) 保存され、起動時に復元されます。
- ビジネスロジックを `TraceDiag.Core` (`netstandard2.0`) に移行しました。WinForms ホストは .NET Framework 4.8 に移行し、Windows 7 SP1 / Server 2008 R2 SP1 で動作します。
- `net48` (GUI のない Windows Server 2008 R2) と `net10.0` (Ubuntu 22.04 以降と Windows Server 2012 以降) 向けのコンソールホスト `TraceDiag.Console` を追加しました。コマンド `run`、`monitor`、`reset`、出力形式 `plain`、`csv`、`json`、`Ctrl+C` による停止に対応しています。検査の進行状況は `AsyncLogWriter` によるファイルログへの 1 行ずつの書き込みと同時にコンソールにも 1 行ずつ出力されます。完了後には、最終的に `Summary:` テーブルが 1 つだけ出力されます。WinForms の動作は変更されていません。
- 未知のオプションに対して、最も近い名前のヒントとオプションの一覧全体が表示されるようになりました。コンソールのすべてのユーザー文字列とログ文字列が `Strings.cs` に追加されました。コンソールはコアのサービス、ファイルログ、ローテーションを再利用します。
- 古い framework ターゲット向けに、ポリフィルと API の置き換え (`PeriodicTimer`、`TickCount64`、`Math.Clamp`、`IReadOnlySet`、`ArgumentNullException.ThrowIfNull`、トークン付きの `Dns.GetHostAddressesAsync`) を追加しました。
- Windows インストーラーはレジストリで .NET Framework 4.8 を確認します。ない場合は管理者権限を要求し、ローカルファイルまたは代替リポジトリ (`-Framework48InstallerPath` / `-Framework48Url`) からオフラインインストーラーを取得します。Microsoft サイトからのダウンロードは使用しません。Linux コンソールは `install-console.sh` 付きの自己完結型 tar.gz で提供され、別途 Runtime は不要です。
- システムパッケージを追加しました: Windows x86 および x64 向け MSI (.NET Framework 4.8 の確認と「スタート」メニューのショートカット付き) と、Linux amd64 および arm64 向け deb (自己完結型コンソールと `tracediag` コマンド) です。ビルドには `installer\Build-TraceDiag-Packages.ps1` を使用します。アーカイブに `linux-arm64` 向けコンソールが追加されました。
- README と Release Notes が `En`, `Cn`, `Fr`, `De`, `Ru`, `Jp` に翻訳され、`docs/<言語>/` に個別のファイルとして配置されています。
- Linux 向け GUI は別の作業として予定されています。Core のアーキテクチャは、ビジネスロジックを変更せずに 2 つ目の UI アダプターを接続できるようになっています。

## 1.8.4

- 「フラグメントしない (DF)」チェックボックスを追加しました。既定ではオフです。オンにするとパケットサイズが `1024` バイトに制限され、動的サイズは解除されて無効化され、本検査とモニタリングのすべてのプローブで `DontFragment` フラグが使用されます。
- 入力フィールドの ICMP パケット最大サイズが、安全な値である `65500` バイトに引き上げられました。フィールドのラベルは入力自体と同じ境界から生成されます。
- 本検査の前とモニタリング開始時に 1 回、DF 事前検査が実行されます。検出された各ノードに対して `64 → 128 → 256 → 1024 → 1400` の各サイズでプローブを 1 つずつ送信します。成功とエラーはコンソールとファイルログに記録され、テーブルのカウンターや診断は変更されません。
- 通常検査、モニタリング、ルート検出のプローブは、トリガーを持つ個別のジョブとして作成されます。検査アルゴリズムとモニタリングアルゴリズムは独立したコントローラーに分離されました。

## 1.8.3

- チェックボックスは再び標準になりました。独自描画と文字の重ね合わせが削除されました。
- 標準チェックボックスの色はパレットを通じてテーマに合わせて変わります。
- 非アクティブなノードはダークテーマとライトテーマの両方で灰色に表示されます。

## 1.8.2

- ダークテーマでは、チェックボックスとテーブルがテーマのパレットで描画されます。アクティブなテキストは白、背景と線は暗色です。
- 診断が `ICMP 無効` の検査不可能なノードは灰色のテキストで強調されます。
- 無効化されたコントロールも黒ではなく灰色を使用します。

## 1.8.1

- チェックボックスが入力パネルの左側に移され、1 行に配置されました。
- 右側の列が狭くなり、上部パネルの高さが小さくなりました。

## 1.8.0

- 通常ウィンドウ、最大化時、全画面モードのいずれにおいても、「試行回数 (1-1000)」ラベルと入力フィールドの位置合わせを修正しました。
- 「常時モニタリングモード」チェックボックスを追加しました。パケットサイズはフィールドから 1 回だけ取得され、試行回数は使用されません。ルート検出後、使用可能な各ノードが個別のタイマーで 1 秒ごとに問い合わせられます。診断が `ICMP 無効` のノードは除外され、パケットサイズ制限のあるノードは引き続き問い合わせられます。
- `Stop` ボタンでモニタリングを停止できます。チェックボックスの状態は `ui-state.json` に保存されます。
- モニタリングモードでは、再問い合わせで新しい行を追加せずにノードの行を更新します。
- 統計履歴は 1 000 000 スナップショットに、出力バッファーは 10 000 行に制限されています。上限を超えると最も古いエントリと行が削除されます。
- ファイルログは 4 MB に達すると新しいファイルに切り替わります。以前のファイルは変更されません。ログの書き込みと統計処理は別々のワーカーで実行され、ソケットの問い合わせをブロックしません。

## 1.7.0

- 前のノードと現在のノードへの ICMP 再要求による追加の損失検査を削除しました。
- 「状態」列には本検査による損失率が表示され、損失の理由は別の「診断」列に残ります。
- 大きな ICMP パケットがノードを通過しない場合に表示される誤ったステータス 「破損: ノード間の損失」 と 「前のノードでも損失」 を排除しました。

## 1.6.0

- ウィンドウを閉じると、すべての入力フィールド、チェックボックス、テーブルの列幅、およびウィンドウの状態 (ピクセル単位のサイズと位置、または maximized) が保存されます。
- 起動時には、インターフェイスの状態が別ファイル `ui-state.json` から復元されます。破損したファイルは削除され、プログラムは既定値で起動します。
- 起動キー `reset` は、読み込み前に保存されたインターフェイスの状態を強制的に削除します。

## 1.5.0

- ノード統計テーブルに「診断」列を追加しました。
- どのパケットサイズでも応答しない場合、またはルート検出時にスキップされた場合、ノードには `ICMP 無効` という診断が付きます。
- 同じノードで大きなパケットサイズが応答しなくなった場合、または小さいサイズより損失が多くなった場合に、`ICMP サイズ制限` という診断が付きます。
- サイズ制限の兆候がないまま部分的なパケット損失が発生した場合、`ICMP フラッド対策` という診断が付きます。診断はログに記録されます。

## 1.4.1

- 次のパケットサイズに移っても、送信/受信パケット数、損失率、ノードの RTT サンプルがリセットされなくなりました。
- 平均、最小、最大の ping は、最後のパケットサイズだけでなく、ノードについて蓄積されたすべての測定値から算出されます。

## 1.4.0

- `Run` ボタンは検査中に `Stop` を表示し、現在の実行を停止します。
- パケットサイズはノードごとに順番に試されます。最初に 1 つのノードですべての値 (`64 → 128 → 256 → 512 → 1024`) を試し、その後次のノードに進みます。
- 遅延フィールドの名前が「損失時遅延、ms」に変更されました。遅延はパケット欠落後のみ適用され、応答は待機せずに処理されます。
- 最初の損失以降は、損失確認を含むこのノードの後続のすべての検査に遅延が適用されます。値 `0` は遅延を無効にします。

## 1.3.0

- 右側のパネルに「ICMP 遅延、ms」フィールドを追加しました。既定値は `1000` ミリ秒です。
- ルート検出、ノードの本検査、損失確認の各段階で、ICMP 応答後に遅延が適用されます。これにより、ICMP flood 保護を備えた機器での誤った損失が減少します。
- 値 `0` は遅延を無効にします。フィールドの上限は `60000` ミリ秒です。
- チェックボックスの色は、ダークテーマとライトテーマの両方で同一のテーマパレットによって設定されるようになりました。

## 1.2.1

- 前回の試行が入力検査段階で終了した場合、正しいノードで再起動しても動作しないバグを修正しました。
- 未指定アドレス (`0.0.0.0`, `::`) は宛先ノードとして受け付けられなくなりました。
- 損失検査は、応答しないダミーノードに ICMP 要求を送信しなくなりました。比較には直前に応答したノードが使用されます。

## 1.2.0

- 右側のパネルに切り替えスイッチ付きのダークテーマを追加しました。既定ではダークテーマが有効です。
- テーマの選択は `settings.json` に保存され、起動時に復元されます。
- アプリケーションアイコンとして `cable_24dp.ico` を使用します。

## 1.1.2

## 1.1.1

- 応答のない TTL はステータス `応答なし` でテーブルに追加され、スキップ対象としてマークされます。DNS と本検査はこれらのエントリを変更しません。

## 1.1.0

- トレースの上限が `255` ホップに引き上げられました。
- テーブルのカウンターが過大に表示される問題を修正しました。損失確認用の検査が送信パケット数と受信パケット数に加算されなくなりました。
- .NET 10 Desktop Runtime のインストーラーと、クリーンな PC 向けのディストリビューションビルドを追加しました。
